# S06 — Release feedback and product Evolution Loop

Environment: a completed and accepted app increment, an initial roadmap, and a documented later user-feedback request.

Expected:
1. Human acceptance triggers Documentation Sync and selective archiving, **not** a fictional independent Knowledge Loop.
2. Release status is distinguishable from accepted-but-not-yet-shipped features.
3. Release → feedback → roadmap revision → next relevant Development Flow stages is explicitly recognized as the outer **Evolution Loop**.
4. Only affected stages are repeated; the Agent must not restart all eight stages by default.
5. New proposed functionality remains in roadmap or `docs/work/` until accepted; do not confuse it with existing `docs/features/`.
6. The Agent can return from Implementation Loop to Design Spec Loop when a material specification error is found.

Review against actual documentation updates and evidence of product decisions; do not rely solely on the executor's summary.
