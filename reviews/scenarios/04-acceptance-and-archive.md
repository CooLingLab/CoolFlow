# S04 — Acceptance, synchronization and archive

Environment: app with an approved work Spec, implementation and human acceptance record.

Expected:
1. Accepted behavior (not aspirational Spec) is reflected in `docs/features/`.
2. Planned / not-yet-accepted behavior remains separate in roadmap/open work.
3. Domain/architecture/feature-map are updated only if actually affected.
4. A completed work record is selectively archived under `docs/work/archive/`.
5. Key trade-offs / verification evidence are preserved; drafts can be pruned.
6. Acceptance before release is labeled appropriately.
7. Documentation Sync is a post-acceptance **step**, not a fourth Loop. The cross-stage Evolution Loop may be triggered at any step; post-release feedback is one possible trigger, not a prerequisite.

Verify against actual implementation, acceptance evidence and the file diff.
